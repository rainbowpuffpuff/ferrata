# State sizes and costs against accumulated state (RFP-021 P.7, P.9; RFP-022 P.7, LEZ side)

Generated by `bash bench/perf/state.sh` (`lez/harness/src/bin/perf_state.rs`). **Measured** in LEZ v0.4.0-rc1's own
state machine (`lee::V03State`, the in-process harness, public transactions executed and settled with LEZ's fee
settlement; nothing here is proven, nothing needs to be). A LEZ node persists this state as borsh-serialized
breakpoints (`lez/storage`: `BreakpointCellOwned(V03State)`), so the **serialized state** column is what a node writes
for it before RocksDB's compression; an account in it is its 32-byte key and its borsh `Account` (nonce, then the
programs' actor states). Records added for K are copies of a real record (or nullifier, burn record) at keys no
request reads: the program reads records by key only, so the copies weigh on the state exactly as real ones and the
statements cannot see them; the accounts measured in sections 1 and 4 are written by real transactions. Every
charge in sections 2 and 3 is asserted equal at every K before it is printed.

Measured 2026-11-21 on the build box (a Modal container: 16 CPUs and 64 GiB at most; its CPU model is not reported inside the sandbox), commit eecd5208 (the binary of that commit; this file's later commits change nothing it measures).

# Requirement status, row by row

The status of every row of [traceability.md](traceability.md): 64 rows for RFP-021 and 73 for RFP-022. The
classification is the project's own, made on 18 November 2026 and updated on 27 November 2026 from the matrix as it
stands at this commit, and it is strict on purpose. A row is **shown** only if every clause of the requirement, as the
RFP words it, is demonstrated today by a named test or a recorded run on real code: LEZ v0.4 release candidates' own
state machine (the in-process harness) or one of their sequencers for the LEZ side, a local EVM or Sepolia for the
Ethereum side. Proofs in RISC Zero dev mode count only where the requirement is not about proving. A row is
**in part** when a clause is demonstrated and another is not, when the behaviour is narrower than the RFP
asks, when the only run is in the native core or in an in-process stand-in for a component the requirement
names, or when a required document exists only as a first draft. **not yet** means no clause is demonstrated,
or the row is neither offered nor built. **waits on Logos** means the requirement names LEZ testnet 0.4 or another
upstream component that is not released; the reason says what is shown instead. A trust assumption or a missing upstream
library that the matrix states as a condition is given in the reason and does not by itself lower a status.
Where a choice was open, the weaker status was taken. Every sequencer named here is one we ran; none is a LEZ network
Logos runs (LEZ testnet 0.4 does not exist). LEZ v0.4.0 was released on 27 November 2026 (RISC Zero 3.1.0, so new program image ids, and new transaction and fee formats); everything here ran on its release candidates (rc1 to rc3, RISC Zero 3.0.5), and the port to v0.4.0 has not started. One of ours is reachable publicly: a LEZ v0.4.0-rc3 network with its own
Logos Blockchain node, named where it is used. Numbers in the Evidence column are rows of [EVIDENCE.md](EVIDENCE.md);
nothing here is audited.

# Release engineering: one command for every number, every M0 check and every release

**Milestones M0, A4 and B4. Written 11 November 2026.** The proposal promises that `just bench` regenerates its
performance numbers with real proving and records the hardware (§B8), that `just m0` prints every M0 check with
its value (M0), and, for A4 and B4, releases ready for testnet 0.4 and a deployment that is one command on the day
it opens. This note says what each command does, what it was run on and what it gave. Paths are relative to the
repository root. Labels as elsewhere: **measured** (a run, with where it ran), **derived**, **estimated**,
**not built**. The code is a prototype, not audited and not for production.

| Command | Script | What it does | Where it runs |
|---|---|---|---|
| `just bench` | `scripts/bench.sh box`, `scripts/bench_report.py` | hardware record, the vault's gas, the light-client cycles, a real proof of the release program; `bench/report/<UTC time>-<commit>/REPORT.md` | the build machine (`FERRATA_BOX`) |
| `just bench-user` | `scripts/bench.sh user-stage`, `user-prove` | the user-side proofs (private attestation, claim, burn, padded as LEZ's wallet pads) proven for real in containers held to `BENCH_CPUS` CPUs (default 16, the declared minimum) and 16 GiB | build machine, then Modal (`BENCH_MODAL_PROFILE`) |
| `just m0` | `scripts/m0.py` | the four M0 checks with their measured values and GO / NO-GO / OPEN; `--online` re-reads the upstream tags; `--json FILE`; `--strict` | anywhere (Python standard library) |
| `just release VERSION` | `scripts/release.sh`, `scripts/release_manifest.py` | builds the six guests (at the crown build path), the vault and the CLI; packages them with `MANIFEST.json` and `SHA256SUMS`; verifies; records the manifest in `releases/VERSION/` | the build machine |
| `just release-verify DIR` | `scripts/release.sh verify` | every checksum, the manifest, the LEZ programs' image ids recomputed with `r0vm` | anywhere |
| `just deploy-testnet ...` | `scripts/deploy-testnet.sh` | deploys a release on a LEZ testnet and an EVM chain; plan only unless `--send` | the deployer's machine |
| `just halmos-long` | `scripts/halmos-long.sh` | the four Halmos properties that did not finish in 900 s, with a longer budget | the build machine |

`FERRATA_BOX` is a command prefix that runs a shell command on a build machine; empty, the stages run where `just`
runs. For this project's Modal build box: `FERRATA_BOX="../modal-build/mrun --profile <workspace> --"` and, to bring
a built bundle back, `FERRATA_BOX_FETCH="../modal-build/mrun --profile <workspace> --no-sync --get"`. Every recipe is
a thin wrapper of a script that runs without `just` too.

## 1. `just bench`: the performance numbers again, with the hardware

`scripts/bench.sh` has one stage per kind of number; `just bench` runs the build machine's four in one call and then
writes `REPORT.md` beside their logs, each figure next to the proposal's (§B8):

| Stage | Regenerates (proposal §B8 row) | How | Proof |
|---|---|---|---|
| `hw` | the hardware line of every figure | `/proc/cpuinfo`, `nproc`, affinity, the cgroup's CPU and memory limits, `/proc/meminfo`, kernel, `rustc`, `r0vm`, `forge` → `hardware.json` | none |
| `gas` | Vault (P.3): deposit, checkpoint under (A) and (B), release; root import's Ethereum side | `forge test --isolate --match-contract 'GasScenarios\|ReturnLegGas' -vv` (Foundry's schedule; `ReturnLegGas` runs RISC Zero's real Groth16 verifier on recorded seals) | recorded seals |
| `cycles` | Update (021 P.1, P.2): the public steps, the largest step, the on-chain path | `bench/run.sh blst-accel --modes onchain,single-onchain,coresplit,steps` (r0vm 3.0.5's executor on mainnet data) | none (cycle counts) |
| `release-proof` | User proving (P.4): the release receipt | `ferrata-e2e prove` with `RISC0_DEV_MODE=0` on the crown rehearsal's private burn, then `ferrata-e2e verify`; GNU time for wall clock and peak memory | **real** (succinct receipt, verified) |
| `user-stage` + `user-prove` (`just bench-user`) | User proving (P.4) and M0 check 1: private attestation, claim and burn, padded as LEZ's wallet pads | builds `prove_attest` and `prove_bridge`, stages them with their fixtures (`lez/scripts/stage-prove-*.sh`), then `lez/results/p4-minimum/minimum.py` in Modal containers whose CPU and memory request equals their limit; every transaction settled with its receipt verified, one flipped bit refused | **real** |

Not regenerated by `just bench`, and why: the GPU figures (the update in 49.5 s, the private attestation in 16.1 s,
the checkpoint proofs in 14.0-219.3 s on one L4) need a GPU workspace and its CUDA build of r0vm
(`gpu-prover/`); the Sepolia figures (live gas under Glamsterdam) need Sepolia, and nothing here sends to a public
network; LEZ execution gas and state growth come from the in-process harness (`lez/`, `cargo test -p harness`),
which `just bench` does not wrap yet; latency is a sum of measured parts (docs/performance.md P.5).

## 2. `just m0`: the open checks with their values

`scripts/m0.py` prints the proposal's four M0 checks, each with its GO condition, the measured value read from the
result file it names, and a verdict: **GO**, **NO-GO** (measured and failed, or not built: the proposal's
"Otherwise" applies) or **OPEN** (not measured yet, or someone else's answer). Nothing is typed in: user proving
comes from `lez/results/p4-minimum/summary-pad.json` and `summary-scale.json` (or `--p4 DIR`, the output of a fresh
`just bench-user`); the gas drop is looked for as a named test (`fn *gas_drop*` in `lez/`, `bridge/`, `cli/`,
`e2e/`); the two upstream facts (the newest LEZ tag, the token program's state) carry their source and date and
`--online` re-reads the tags with `git ls-remote` (read-only). The declared minimum is 8 cores with 16 threads, so
the 16-CPU containers are the minimum and the 8-CPU ones are shown below it.

Output of `just m0` on 11 November 2026 (on the build box, `just` 1.36.0; the same on any machine, it reads files):

| Check | GO when | Measured | Verdict |
|---|---|---|---|

At 8 threads the attestation takes 20.6 min (NO-GO there) | **GO (Linux); macOS OPEN** |
| 2. The gas drop | passes | no test of it in the repository | **NO-GO (not built)** |
| 3. Token program on v0.4 | pinned, or ported by me in B2 | released for v0.2.4; the v0.4 port is an unmerged branch | **OPEN (the B2 port)** |
| 4. Summary line: 1 of 4 checks GO. The "Also in M0" items (Logos's answer on `ferrata_attestor`, testnet 0.4's
parameters, a notice period, an engineer's check of the finality conditions, audit quotes) are printed as OPEN.

# Porting Ferrata from LEZ v0.4.0-rc3 to LEZ v0.4.0

**Status of 28 November 2026, 08:27Z. The port is in progress: nothing on this page claims that Ferrata works on
v0.4.0 beyond what the Status column shows, and every status other than "not started" names its evidence.**

The port was developed on unpublished branches and published as one commit, `6a539b7f` ("LEZ v0.4.0 port"), on
`fb27c1e2`; the building commits below are that commit, and commit ids in the port's run records written before
it name the unpublished history, whose content is all in `6a539b7f`.

Ferrata's test network and its builds run LEZ v0.4.0-rc3 (commit `bafd07be`); the repository's committed selection is
v0.4.0-rc1, and earlier records ran on rc1 and rc2, each selected by
[`lez/scripts/lez-select.sh`](../lez/scripts/lez-select.sh). LEZ v0.4.0 (tag `v0.4.0`, commit `a255b42c`, the merge of
[logos-execution-zone#1155](https://github.com/logos-blockchain/logos-execution-zone/pull/1155); released 27 November
2026 04:06Z; `v0.4.0-rc4` is the same tree: both commits have git tree `3049ef30`) is 127 commits and 34 merged pull requests after rc3 (`git diff --stat
bafd07be a255b42c`: 516 files). This page lists every change in that range that touches Ferrata, the Ferrata files it
touches, the piece of the port that owns it, and its status. The release notes' other breaking entries (#985, #993,
#996, #1035 and #987, the wallet's sealed storage) were already in rc3, which Ferrata runs today. The tags and LEZ's
RISC Zero pins at each, as GitHub listed them on 28 November 02:15Z, are in
[`port-v0.4.0/lez-tags.json`](port-v0.4.0/lez-tags.json).

## How the port is done

- **rc3 stays supported.** The deployed test network runs rc3 (and the B1 bridge program) until it is redeployed.
  v0.4.0 is a new selector tag, `lez-select.sh v0.4.0` (Cargo feature `lez-040`), added as rc2 and rc3 were; every
  default, committed lockfile and CI job keeps doing what it did before the port (the committed selection stays rc1;
  the test network's builds stay rc3), and v0.4.0 gets its own CI steps.
- **Behaviour that changes on the release candidates' paths**, on purpose: `ferrata deposit` with `--sequencer` or
  `FERRATA_SEQUENCER` set reads the network's LEZ version first, also on a dry run, so an unreachable sequencer stops
  it; the web wallet reads the version again before every LEZ-dependent signature (one more request each); CI's
  `roundtrip` job also runs `cargo test --locked --test lez_version`; `deploy/testnet/deploy.sh`'s host commands now
  fail the call when the host's command does not end in Success; `checkpoint/attestor/zone.sh` refuses a `ZONE_LEZ`
  tree whose name is not `lez-` and a known tag or commit.
- **Four pieces**, each on its own branch from `fb27c1e2`, integrated into `lez-040`:
  - **core** (`lez-040-core`): the selector, manifests, lockfiles, the guests on RISC Zero 3.1.0 and their image ids,
    the harness, the wire crates;
  - **zone** (`lez-040-zone`): local v0.4.0 sequencers (standalone and a zone of four keys), the sequencer CI, the
    attestor's zone scripts, the test network's deploy scripts for v0.4.0, end-to-end runs on v0.4.0;
  - **clients** (`lez-040-clients`): the `ferrata` CLI and its wallet, the Logos modules, the chain service, relayer
    and monitor, `lez-read`, the web wallet and explorer (transaction, fee, receipt and wallet formats);
  - **verify** (`lez-040-verify`): this page, SPEL and the IDLs on v0.4.0, the `verify` checks, the docs and rows.
- **Status words**: *not started*; *building* (work on a piece's branch, named by commit); *tested on v0.4.0* (a named
  test passes against v0.4.0; the command is in the Evidence column); *recorded run* (a run on v0.4.0 is recorded in
  the repository; its path is in the Evidence column). A row takes the weakest status of its parts, and moves only on
  evidence that exists; `python3 -I scripts/verify.py lez040-catalogue` holds the Evidence column to that.

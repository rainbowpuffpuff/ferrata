Accessibility

We aim for WCAG 2.2 level AA on every page of this site. This statement says what we checked, how, what fails today, and what we have not checked. It does not claim conformance.

How it was checked

  • axe-core (version pinned by its sha512) injected into each page after it loaded and its scripts settled, in Chromium and in Firefox, at a desktop width (1366 px) and a phone width (390 px), in light and dark colour schemes: four runs per page. Tags: wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa, best-practice.
  • Keyboard: Tab pressed through each page (up to 400 stops) recording every focused element: whether focus ever stops on something hidden, whether it is visibly outlined, whether a skip link is the first stop, and whether focus gets stuck.
  • The script is scripts/a11y/check.py in the repository; the record names the versions it ran with and the address it checked.

What these checks cannot tell

  • Automated rules find only part of the accessibility problems a page can have. No screen reader user has tested this site; no manual audit against all WCAG success criteria has been done.
  • Pages that build their content from live chain data were checked in the state they reached within a few seconds; dialogs and states reached only by interaction were checked only where the keyboard pass opened them.
  • Zoom to 400% and text spacing were not tested systematically.

Who fixes what

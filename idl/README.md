## Format

SPEL's IDL (`SpelIdl` of `spel-framework-core` 0.7.0, `logos-co/spel` at `c6f73ce`, its
`docs/reference/idl.md`). SPEL's stable release targets LEZ v0.2.4, and both programs are written
against LEZ v0.4 directly, so the IDL is hand-written and checked rather than generated by SPEL's
macros. It uses SPEL's fields as SPEL defines them:

- `instruction_type` names the program's message enum (`ferrata_lez_wire::Message`,
  `ferrata_lez_bridge_wire::BridgeMessage`), which SPEL documents for programs with an external
  instruction enum. Each instruction's `variant` is its variant, its `discriminator` the one-byte
  borsh variant index that starts the message, and its `args` the variant's fields in order.
  The message is borsh: what `discriminator ++ borsh(args)` gives is exactly what the program decodes.
- `accounts` of an instruction: the actors a transaction sending it lists, as the harness's
  transactions list them (`lez/harness/src/lib.rs`, `bridge.rs`): the receiver first (LEZ v0.4
  delivers each message to one actor), then the actors it reaches through the messages it sends.
  A bridge message that reads an attestation record lists it as `attestation_record`, with `owner`
  `ferrata_attestation` (that program's `header(instance, slot)`). Optional actors say when they
  are listed. `pda.seeds` lists the
  derivation's inputs; the hash is Ferrata's, not SPEL's: `SHA-256(domain || tag || parts)` with
  domain `ferrata-lez/v1/` (attestation) or `ferrata-lez/v1/bridge/` (bridge), then LEZ's
  `AccountId::for_public_pda(program, seed)`. A tool that derives SPEL's own PDAs from these seeds
  gets other accounts.
- `accounts` (top level): the actor states, for decoding an account's data (`spel inspect --type`).
- `errors`: every one-byte exit code the program refuses with, with the source's first doc line.
  The attestation program passes on the core's codes (1-61, 100-199) and the step API's (80-99)
  beside its own (200-219); the bridge program's are 240-255.
- Fields SPEL does not define (`docs`, `internal`, `x-rust`) are ignored by SPEL's deserializer.
  `internal: true` marks a message the program accepts only from another of its own actors.
- Types are in SPEL's grammar only: primitives, `vec`, `option`, `defined`, `array`. A Rust tuple
  (`Vec<(Root, u128)>` in `Spend`) is the struct `FeeShare` with fields `"0"`, `"1"`; a tuple
  variant (`Field::Topic(u8)`, `BridgeState::Config(ConfigState)`) has fields `"0"`, ... .
  `[u8; 32]` values are written `{"array": ["u8", 32]}`; LEZ's `AccountId` is `account_id`.

## The check

```sh
python3 -I idl/check.py     # CI job `idl`; standard library only
```

For each program it checks, and prints one line per check:

1. the JSON has the shape of `SpelIdl`, and every type is in SPEL's grammar;
2. each instruction is the variant of `instruction_type` its discriminator indexes, with its fields;
3. every vector decodes, **using only the IDL**, to exactly its bytes; rendered in Rust's `Debug`
   syntax it equals the `Debug` text the Rust wire wrote beside it (so every field name, order,
   width, variant index and value agrees); a message decodes the same through the instruction
   table; re-encoding the decoded value gives the same bytes;
4. coverage: every instruction, type and enum variant is decoded at least once;
5. the IDL's errors equal the program's `code::ALL` (and the core's and step API's codes);
6. each vector with a byte removed, a byte appended or an out-of-range variant index is refused;
7. IDL mutants (two fields swapped, a field renamed, a u64 read as u32, a variant removed, an
   `Option` read as plain) are each rejected by check 3;
8. PDAs: the account of every actor kind (`instance`, `job`, `header`; `config`, `token`, `root`,
   `nullifier`, `burn`, `holder`), written by the wire's own functions, and two real `header`
   accounts printed by `ferrata-attest`, are derived again from what the IDL documents alone (the
   domain in its `docs`, the tag and arguments of the account's `pda.seeds`, the encodings) and
   LEZ v0.4's `AccountId::for_public_pda` (`SHA-256("/LEE/v0.2/AccountId/PDA/" ‖ 0⁸ ‖ program ‖ seed)`).

The decoder follows SPEL's own (`spel-framework-core/src/decode.rs`).

The vectors come from [`lez/bridge-wire/tests/idl_vectors.rs`](../lez/bridge-wire/tests/idl_vectors.rs),
which builds a value of every message and actor state with distinct field values. Its matches have
no wildcard arm: a new variant in either program stops it compiling until a vector, and with it an
IDL entry, is added. It runs with `lez/` (LEZ's sources beside the repository, as `lez/RESULTS.md`
says), and fails when the committed vectors differ from what the wire encodes:

```sh
cd lez
cargo test --locked -p ferrata-lez-bridge-wire --test idl_vectors                      # compare
FERRATA_IDL_WRITE=1 cargo test --locked -p ferrata-lez-bridge-wire --test idl_vectors  # rewrite
```

When the programs change: rewrite the vectors, edit `tools/build_idl.py` (or the JSON), rerun it,
and run `check.py` until it passes.

## Real messages

Two more modes decode real messages with the IDL alone and compare each with its Rust `Debug` text:

```sh
# one message, as ferrata-attest --message-out writes it (lez/ATTEST-CLI.md)
python3 -I idl/check.py --decode ferrata_attestation Message message-2.hex message-2.debug
# every attestation-program message in recorded LEZ blocks
cd lez/live/driver && cargo build --locked --bin idl-recorded      # needs libpcsclite-dev, as the driver
target/debug/idl-recorded OUT.json lab ../../lab/results/record/blocks.borsh ../../lab/results/record/programs.tsv \
  live ../results/blocks.borsh ../results/programs.tsv
python3 -I ../../../idl/check.py --recorded OUT.json
```

`idl-recorded` ([`lez/live/driver/src/bin/idl-recorded.rs`](../lez/live/driver/src/bin/idl-recorded.rs))
reads each block log with LEZ's own types, takes every public transaction whose root message goes to
the attestation program (the programs named in `programs.tsv`, less LEZ's `scripted` test program),
and writes the message's bytes and its `Debug` text from `ferrata_lez_wire::Message`. A message that
today's wire cannot decode (a run recorded with an older image) is counted, not written.

## SPEL's own code reads it

[`spel-check/`](spel-check/) is a small crate on `spel-framework-core` 0.7.0 itself (the clone of
logos-co/spel at `c6f73ce` beside the repository, at `upstream/spel`): it deserializes both files
into SPEL's `SpelIdl` (so SPEL's parser accepts every field, including the extra `docs`) and decodes
every vector, and every recorded message given as an argument, with SPEL's own borsh decoder,
requiring every byte to be consumed (`decode_account_data_try_all` over an IDL whose `accounts` holds
just the vector's type). SPEL renders 32-byte arrays as `Public/<base58>` account ids, which is a
display choice; the bytes and the structure are what is checked.

```sh
cd idl/spel-check && cargo run --locked -- [RECORDED.json]      # exit status 1 on any failure
```

## Results

Measured on the Modal build box (`mrun`, 11 November 2026) and in CI's command:

- `idl_vectors`: 2 passed (19 attestation vectors, 37 bridge vectors).
- `check.py`: attestation 19 vectors, 13 of 13 instructions, 19 types, 31 enum variants, 68 codes,
  5 of 5 mutants rejected; bridge 37 vectors, 20 of 20 instructions, 29 types, 34 enum variants,
  16 codes, 5 of 5 mutants rejected.
- `--decode`: three of `ferrata-attest`'s messages (7,201, 2,153 and 31,654 bytes, built from real
  Sepolia proofs) equal to their `Debug` text ([`lez/results/attest-cli/idl-decode.txt`](../lez/results/attest-cli/idl-decode.txt)).
- `--recorded` ([`results/recorded.txt`](results/recorded.txt)): 317 messages of the attestation
  program, 2,646,210 bytes, from the lab's blocks (250 of 250: `Init` 2, `Open` 58, `Miller` 58,
  `Adopt` 74, `Finish` 58) and the live run's (67), each decoded by the IDL alone to its `Debug`
  text. 6 more messages of the live run are of an older wire, which today's Rust wire does not
  decode either (the first: block 18, transaction 0).
- `spel-check` ([`results/spel-check.txt`](results/spel-check.txt)): both files parsed as SPEL's
  `SpelIdl`; SPEL's decoder decoded 19 of 19 and 37 of 37 committed vectors and 317 of 317 recorded
  messages exactly.
- check 8: 11 accounts derived from the IDL's documented seeds equal the wire's and the CLI's
  (`vectors/pda.vectors.json`, `vectors/pda-recorded.json`).
